# M4: implants, complications and follow-up (draft, awaiting approval)

M4 completes the record of an operation after the procedure rows: what was implanted, what went wrong, and how the
patient was at fixed times afterwards. Accepted when a made-up case can be followed from the operation to 12 months:
implants with maker and sizes, one complication with a reoperation linked to it, follow-ups at 6 weeks, 3 and 12
months with scores, and the 12-month visit shown as due before it happens.

## A. Implants (changed from the data dictionary)

The dictionary records implant category, count and maker only. That cannot answer "which cage height at L4-L5" or
"breach rate for 6.5 mm screws". M4 records each implant group with its maker, product and sizes.

**One row per group of identical implants** (same category, maker, product and size), with its count and its levels:
two 6.5×45 screws at L4 and two 6.5×50 at L5 are two rows. One row per screw would be slow to enter for no gain.

| Field | Type | Req | Values / units |
| --- | --- | --- | --- |
| implant_category | enum | C | the dictionary's list; proposed additions: `rod`, `interspinous_device`, `bone_graft_substitute` (surgeon decides) |
| company | ref | C | managed list of companies (admin page, like hospitals); a company is retired, never deleted |
| product | text | E | product or system name as on the label (e.g. a screw system or cage family); suggested from earlier entries for the same company |
| count | int | C | ≥ 1 |
| levels | levels | C for spinal | same notation and validation as procedure rows |
| side | enum | E | left, right, bilateral, midline |
| parameters | per category | C/E | see the table below; numbers with units, checked against a sensible range |
| procedure_row | ref | E | the procedure row the implant belongs to (the screws to `pedicle_screw_fixation`, the cage to `interbody_fusion`) |

**Parameters per category** (the field set, not clinical facts; units fixed so values can be compared):

| Category | Parameters |
| --- | --- |
| pedicle_screw, lateral_mass_screw | diameter (mm), length (mm), cannulated yes/no, fenestrated/cement-augmented yes/no, placed by robot yes/no, breach grade per screw from post-op CT (Gertzbein-Robbins A–E) |
| rod | diameter (mm), length (mm), material (titanium, cobalt-chrome, PEEK), pre-bent yes/no |
| cage (PLIF/TLIF, ALIF/LLIF, ACDF) | height (mm), width (mm), length (mm), lordosis (°), material (PEEK, titanium, 3D-printed titanium, other), expandable yes/no, graft inside (autograft, allograft, substitute, none) |
| cervical_disc | height (mm), footprint (size label or W×D mm) |
| plate | length (mm), levels spanned |
| vertebral_augmentation_cement | cement volume (ml) per level, balloon/cavity yes/no |
| interspinous_device | size (mm) |
| bone_graft_substitute | type, volume (ml or cc) |
| shunt_valve | valve type (fixed, programmable, anti-siphon), opening pressure / setting (cmH₂O or the maker's performance level), distal site (peritoneal, atrial, pleural), lumbar-peritoneal yes/no |
| external_drain | site (ventricular, lumbar) |
| neurostimulator_lead | lead type (percutaneous, paddle), contacts (number), tip level |
| IPG | rechargeable yes/no, implant site |
| intrathecal_pump | reservoir (ml), drug |
| cranioplasty_implant | material (autologous bone, PEEK, titanium mesh, PMMA, hydroxyapatite, other), custom-made yes/no |
| other | description (required) |

The parameter list per category lives in `vocab/implants.yaml` (category → parameters with unit, type and range), so a
new parameter is a vocabulary change, not a schema change. Values are stored as JSON on the implant row and can be
filtered on (for example cage height 10–12 mm).

**Still no lot or serial numbers**, as decided in the dictionary: traceability stays in the hospital record. If the
group wants them, this is the place to reverse that decision.

**Operation-level fields move off the implant table:** guidance duplicates the procedure row's technology and is
dropped; fluoroscopy time and adjuncts (5-ALA, ICG…) move to the operation.

**Entry:** an "Implants" section on the operation form with chips for category and company; the parameter fields
appear for the chosen category; presets can carry implant rows (e.g. a usual cage). The quick line's `@υλ` tag
proposes an implant row (dashed, suggested) the same way it proposes procedures. Search gains company, product,
category and parameter filters.

## B. Complications

As in the dictionary: one row per complication, up to 90 days, type from `vocab/complications.csv`, timing, onset
date, Clavien-Dindo grade, treatment, outcome at 90 days, related to surgery, detected by. A complication treated by
reoperation links to the new operation, and that operation shows which complication it treats. Late complications of
earlier surgery (implant failure, CSF leak…) stay diagnoses that link to the index operation, as decided 2026-11-15.

## C. Follow-up and scores

Visits at 6 weeks, 3, 12 and 24 months (24 only for fusion and tumour cases), plus unscheduled ones. A visit outside
its window is stored as unscheduled. Each visit records status (seen, phone, lost, died, declined), neurological
status, the condition-specific outcome (fusion, tumour, seizures, trigeminal numbness by branch), and states "no
complication" explicitly. Scores (VAS, ODI, NDI, mJOA, KPS, mRS, EQ-5D, BNI pain and numbness, Engel) are entered at
baseline and at each visit; a score not done carries a reason, never a blank. Which scores are offered depends on the
procedure. A visit can be locked once complete.

## D. Due follow-ups

A list per surgeon of visits due or overdue (window start to end), with the 12-month visit highlighted, so the
secretary has a call list. No e-mail or SMS in M4.

## E. Tests

Unit tests for the parameter ranges and the follow-up windows; the web check enters a full made-up case through
the browser routes and checks the due list and the reoperation link from both sides.
